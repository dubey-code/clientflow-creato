# Платформа брифов и коммерческих предложений (с защитой ПДн по 152-ФЗ)

## Что получится

**Админка (только для вас, вход по email/паролю)**
- Список проектов в таблице: клиент, статус (создан / бриф заполнен / КП готово), ссылка на бриф, ссылка на КП, дата, фильтр и поиск.
- Создание проекта: название, описание задачи, данные клиента (ФИО, телефон, email, компания).
- Конструктор брифа: редактируемый список вопросов (текст, длинный текст, выбор, чекбоксы, бюджет/сроки). Есть шаблон по умолчанию.
- После создания автоматически выдаётся уникальная ссылка на бриф (копирование в один клик).
- Карточка проекта: все ответы, сгенерированное КП, кнопка «Перегенерировать», ручное редактирование текстов КП.

**Публичный бриф для клиента** `/brief/<токен>`
- Красивая форма с вопросами, блоком контактов и согласием на обработку ПДн (обязательно по 152-ФЗ).
- Заметный бейдж: «Ваши персональные данные защищены и не передаются в ИИ — используются только для подстановки в итоговый документ».

**Коммерческое предложение-лендинг** `/offer/<токен>`
- Генерируется ИИ автоматически после отправки брифа: обложка, понимание задачи, решение, этапы и сроки, стоимость, почему мы, призыв к действию.
- Имя клиента, компания и контакты подставляются уже после генерации.
- Внизу — пометка о защите данных.

## Защита персональных данных

```text
Клиент -> ФИО/телефон/email -> шифрование (AES-GCM, ключ на сервере) -> БД
Ответы брифа -> замена ПДн на метки {{CLIENT_NAME}}, {{PHONE}}, {{EMAIL}} -> ИИ
Ответ ИИ (с метками) -> сервер расшифровывает ПДн -> подстановка -> КП
```
- ПДн хранятся в отдельной таблице только в зашифрованном виде; ключ — секрет на сервере, в браузер не попадает.
- В ИИ уходят только описание проекта и ответы без ПДн. Дополнительно перед отправкой текст ответов проверяется фильтром: найденные телефоны/email/ФИО клиента вырезаются и заменяются метками (на случай, если клиент вписал их в свободное поле).
- Доступ к расшифрованным данным — только у администратора; публичные ссылки содержат длинный случайный токен.
- Фиксируется дата и факт согласия клиента; страница «Политика обработки ПДн».

## Технические детали
- Lovable Cloud: аутентификация, таблицы `projects`, `brief_questions`, `brief_responses`, `client_pii` (шифротекст), `offers`, `user_roles` (роль admin), RLS: всё только для admin; публичный доступ к брифу/КП — через серверные функции по токену.
- Шифрование: Web Crypto AES-256-GCM в серверных функциях, ключ `PII_ENCRYPTION_KEY` генерируется автоматически.
- Генерация КП: Lovable AI Gateway, структурированный JSON-ответ (секции лендинга) с метками, подстановка на сервере при отдаче страницы.
- Тесты: функция маскирования ПДн (телефон, email, ФИО вырезаются) и подстановка меток.
- Дизайн: строгий «агентский» стиль — тёмно-графитовый с тёплым акцентом, шрифты Manrope/Sora.

## Ограничение
Полное соответствие 152-ФЗ также требует хранения ПДн граждан РФ на серверах в России и уведомления Роскомнадзора — это организационные шаги вне платформы; инфраструктура Cloud не размещена в РФ. Об этом будет указано, решение технической части не меняется.
